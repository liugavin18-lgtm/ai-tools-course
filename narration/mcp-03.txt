第三章：动手做第一个 MCP 服务。这一章学完，你能从零运行一个完整的服务，不依赖 AI 自己测试它，再把它接到 Claude Code 上使用，还能亲眼看到底层的通信消息。

先准备环境，只需要两样：Python 三点十以上，以及一个叫 uv 的工具，它会自动管理依赖，让你不用为装包烦恼。

然后获取示例代码，在仓库的 examples 目录下，叫 mcp-demo。先运行 make_demo_db 点 py，它会生成一个虚构的销售数据库，里面有五十位客户、五个产品和四百笔订单。所有数据都是随机生成的，没有任何真实信息。

接着来读服务端的代码。整个服务只有一个文件，核心结构只有六个要点。

第一，用 FastMCP 创建服务，给它起个名字。第二，用 mcp 点 tool 这个装饰器，把一个普通函数注册成工具，函数名就是工具名。第三，函数下面那段三引号的说明文字，会被发给 AI，它是 AI 判断什么时候该用这个工具的依据。第四，参数的类型标注，比如月份是字符串，数量是整数，会自动变成参数规范。第五，用 resource 装饰器提供资料，用 prompt 装饰器提供提示词模板。第六，最后调用 run，默认用标准输入输出的方式运行，等 AI 应用来连接。

这里有一个重要的提醒：SDK 的版本要固定。示例文件开头声明的依赖里有一个小于二的限制，请不要去掉它。MCP 的 Python SDK 二点零版本，把 FastMCP 改了名，如果不固定版本，某一天自动升级之后，你的服务会直接起不来。

接下来是本章最重要的一步：不用 AI，自己当客户端来测试。运行 uv run test_client 点 py，你会看到，它先列出服务有哪些工具、资源和提示词，然后依次调用四个工具，都显示成功。再往下是安全测试：删表、改数据、挂载外部数据库、传入非法月份、查询不存在的表，这五条每一条都必须被拒绝，最后显示全部通过。

页面上有这次运行的真实截图。永远先自己测试，再交给 AI 用。尤其是安全测试部分，它证明的是服务真的写不进去，而不是希望 AI 别乱改。

测试脚本里的几行代码，正好对应第一章讲的流程：初始化是握手，列出工具是点名，调用工具就是真正的调用。在网络上传输的，是一种叫 JSON R P C 的消息格式：客户端发出一条调用请求，服务端返回一条结果。

测试通过之后，就可以接到 Claude Code 上了。执行 claude mcp add，名字叫 demo-db，后面接 uv run 和脚本路径。然后新开一个会话，试着问三个问题：我有哪些数据表？三月的销售汇总是多少？最后一个是故意的：帮我删掉订单表。这时 AI 应该告诉你做不到，因为服务根本没有写入能力。

另外，AI 查到数据之后，还可以帮你整理成图表。页面上那张图，用的就是示例库的虚构数据。

最后介绍一个调试利器：官方的 Inspector。它是一个网页调试器，可以手动点工具、看参数和返回结果。写新工具的时候，用它比反复问 AI 快得多。

本章小结：一个 MCP 服务，就是一个 Python 文件加上几个带说明的函数。先脱离 AI 测试，再接入 AI。工具的说明文字和参数类型，就是给 AI 的说明书。

练习一：给服务新增一个工具，返回消费金额最高的若干位客户，并且保证传入负数时不会崩溃。练习二：接入 Claude Code，让 AI 回答哪个城市的客户总消费最高，并核对结果。下一章，我们学习怎么把工具设计好。
