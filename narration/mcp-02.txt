第二章：安装和使用现成的 MCP。学完这一章，你能给 Claude Code 装上本地和远程的 MCP，看懂配置文件，并且会管理和排查已经装好的服务。

在安装之前，先问自己三个问题。第一，这个服务是谁写的？是官方、知名团队，还是来路不明？第二，它能碰什么？能读文件，还是能发邮件，还是会花钱？第三，我愿意给它多大的权限？因为安装别人写的 MCP，等于让一段陌生的程序在你的电脑上运行，并且让 AI 能指挥它。

安装本地服务，格式很简单：claude mcp add，后面依次是名字、范围，然后两个短横线，再接启动命令和参数。比如，把一个叫 demo-db 的服务，装给当前用户的所有项目，就写 claude mcp add demo-db，减 s user，两个短横线，uv run，再加上脚本的绝对路径。注意，路径一定要写绝对路径。如果需要传密钥，可以用减 e 加上变量名和值，通过环境变量传入。

安装远程服务，用 transport http，再加上服务商给你的地址。很多远程服务需要登录授权，第一次使用时，按提示在浏览器里登录就可以了。再次提醒：不要把密码或令牌发给 AI，也不要贴进配置里。

接下来是三种范围。本地范围，只有你自己，只在当前项目有效。项目范围，项目里所有人都能用，配置存在项目根目录的 mcp 点 json 文件里，这个文件可以提交到代码仓库。用户范围，只有你自己，但所有项目都能用。

特别要小心项目范围：因为那个配置文件会被提交到仓库，所以里面绝对不能写密钥。公开仓库就更要检查了。

配置文件长什么样？不管哪个 AI 工具，核心都是三项：名字、启动命令、参数。记住一个口诀：命令加参数，就等于你在终端里敲什么，才能把这个服务启动起来。能在终端里手动跑起来，才有可能被 AI 应用跑起来。

日常管理有三条命令。claude mcp list，查看装了哪些、连接是否正常。claude mcp get 加名字，查看某一个的详细配置。claude mcp remove 加名字，卸载。在对话里输入斜杠 mcp，也能看到连接状态。

怎么用呢？装好之后，新开一个会话，直接说人话就行，不用记任何命令。比如问：我有哪些数据表？AI 会自己挑工具、填参数。第一次调用时，通常会弹出确认，你可以选择允许一次，或者长期允许。

这里有一个特别容易踩的坑：已经开着的会话，不会出现新装的工具。因为 MCP 是在会话启动的时候才连接的，所以装好或者改过配置之后，必须新开会话。

最后，不同的 AI 工具之间有一些小差异。有的用命令添加，有的直接改配置文件。有的工具会按需加载，不会一开始就把所有工具塞给模型，这时如果 AI 说没有这个工具，你可以明确告诉它：请用某某这个 MCP，需要先加载工具。各家的权限确认机制也不同，但思路一致：先问你，再执行。

本章小结：本地服务用命令加参数，远程服务用地址。范围决定谁能用，项目范围会进仓库，所以不放密钥。改完配置必须新开会话。

练习：用 claude mcp list 看看你现在装了哪些 MCP，并对每一个回答：谁写的？能碰什么？下一章，我们动手做第一个 MCP 服务。
