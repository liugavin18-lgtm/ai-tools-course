# 写一个 Skill

## Skill 的结构
一个 Skill 就是一个**文件夹**，里面至少有一个 `SKILL.md` 文件：

```
weekly-report/
└── SKILL.md
```

## 放在哪里

| 位置 | 作用范围 |
|---|---|
| `~/.claude/skills/技能名/` | 你的所有项目都能用 |
| 项目里的 `.claude/skills/技能名/` | 只在这个项目里用 |

## SKILL.md 的写法
文件分两部分：顶部的**说明卡**，下面的**正文**。

```markdown
---
name: weekly-report
description: 生成周报。当用户说“写周报”“本周总结”时使用，按固定三段格式输出。
---

# 周报生成

## 步骤
1. 向用户确认本周时间范围。
2. 收集：已完成事项、进行中事项、下周计划。
3. 按下面的格式输出。

## 输出格式
**一、本周完成**
- 事项 + 结果（尽量带数字）

**二、进行中**
- 事项 + 当前进度 + 预计完成时间

**三、下周计划**
- 事项 + 负责人

## 注意
- 语气简洁，不用夸张的词。
- 数字必须来自用户提供的资料，不要编造。
```

## 最关键的是 description
`description` 决定 AI **什么时候会想起用这个 Skill**。

| 写法 | 效果 |
|---|---|
| ❌ `周报工具` | 太笼统，AI 不知道什么场景该用 |
| ✅ `生成周报。当用户说“写周报”“本周总结”时使用` | 场景和触发说法都写清楚 |

## 写好 Skill 的四个原则

1. **一个 Skill 只做一件事**，不要做成大杂烩。
2. **步骤要具体**，写“确认时间范围”，而不是“做好准备”。
3. **给出输出样例**，AI 照着样例做最稳。
4. **写明红线**，比如“不得编造数据”“不得出现真实客户名”。

## 动手练习
1. 选一件你每周都重复做的事。
2. 按上面的模板写一个 `SKILL.md`。
3. 新开会话，说出触发语，看 AI 是否按你的格式输出。
4. 不满意就改文件，再试。**Skill 是越用越好的。**

!!! tip "进阶"
    Skill 可以和 MCP 配合：Skill 里写明“先用数据库工具查出数据，再按下面的格式写分析”。
