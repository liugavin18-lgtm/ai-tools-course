# 第 2 章　安装和使用现成的 MCP

!!! abstract "本章目标"
    学完你能：① 给 Claude Code 装上本地和远程 MCP；② 看懂配置文件；③ 管理和排查已装的服务。

## 2.1　安装前先问三个问题

安装别人写的 MCP，等于**让一段陌生程序在你电脑上运行，并让 AI 能指挥它**。装之前先确认：

1. **谁写的？** 官方、知名团队，还是不明来源？
2. **它能碰什么？** 读文件？发邮件？花钱？
3. **我愿意给它多大权限？**（详见[第 5 章](05-security.md)）

## 2.2　安装本地服务（stdio）

通用格式：

```bash
claude mcp add <名字> -s <范围> -- <启动命令> <参数...>
```

示例：

```bash
claude mcp add demo-db -s user -- uv run /绝对路径/server.py
```

| 部分 | 含义 |
|---|---|
| `demo-db` | 你给它起的名字，之后用它管理 |
| `-s user` | 范围：见下表 |
| `--` | 分隔符，后面整段都是“服务怎么启动” |
| `uv run ...` | 启动命令。**路径必须写绝对路径** |

需要传环境变量（如密钥）：

```bash
claude mcp add my-svc -s user -e API_KEY=你的密钥 -- npx -y some-mcp-server
```

## 2.3　安装远程服务（HTTP）

```bash
claude mcp add --transport http 名字 https://服务商给的地址/mcp
```

很多远程服务需要**登录授权（OAuth）**：首次使用时按提示在浏览器里登录即可。**不要**把密码或令牌发给 AI 或贴进配置。

## 2.4　三种范围（Scope）

| 范围 | 参数 | 谁能用 | 配置存在哪 |
|---|---|---|---|
| 本地 | `-s local`（默认） | 只有你，只在当前项目 | 你的个人配置 |
| 项目 | `-s project` | 项目里所有人 | 项目根目录的 `.mcp.json`（可提交到 Git） |
| 用户 | `-s user` | 只有你，所有项目 | 你的个人配置 |

!!! warning "项目范围要特别小心"
    `.mcp.json` 会被提交到仓库。**绝不能在里面写密钥**；公开仓库里更要检查。

## 2.5　配置文件长什么样

不管哪个 AI 工具，配置的核心都是这三项：**名字、启动命令、参数**。

```json
{
  "mcpServers": {
    "demo-db": {
      "command": "uv",
      "args": ["run", "/绝对路径/server.py"],
      "env": {}
    },
    "remote-svc": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}
```

!!! tip "读配置的口诀"
    `command + args` = 在终端里敲什么能把它启动起来。
    **能在终端手动跑起来，才可能被 AI 应用跑起来。**

## 2.6　日常管理命令

```bash
claude mcp list            # 看装了哪些、是否连接正常
claude mcp get demo-db     # 看某一个的详细配置
claude mcp remove demo-db  # 卸载
```

在 Claude Code 对话里，输入 `/mcp` 也能查看连接状态和需要授权的服务。

## 2.7　怎么用：直接说人话

装好后**新开一个会话**，不用记任何命令：

> 我有哪些数据表？
> 2026 年 3 月销售额最高的产品是什么？

AI 会自己挑工具、填参数。首次调用时通常会**弹出确认**，你可以选择允许一次或长期允许。

!!! warning "已经开着的会话不会出现新工具"
    MCP 在**会话启动时**连接。装好或改过配置后，必须**新开会话**。

## 2.8　不同 AI 工具的小差异

| 差异点 | 说明 |
|---|---|
| 配置入口 | 有的用命令添加，有的直接改配置文件里的 `mcpServers` |
| 按需加载 | 有的工具默认不把所有 MCP 工具塞给模型，需要先“加载”再使用。如果 AI 回答“没有这个工具”，可以明确要求：“请用 xxx 这个 MCP，需要先加载工具” |
| 权限确认 | 各家的弹窗和白名单机制不同，但思路一致：**先问你，再执行** |

## 本章小结与练习

- 本地服务用 `command + args`，远程服务用 `url`。
- 范围决定谁能用；项目范围会进仓库，**不放密钥**。
- 改完配置**必须新开会话**。

**练习 2.1**　用 `claude mcp list` 看你现在装了哪些 MCP，并对每一个回答：谁写的？能碰什么？
