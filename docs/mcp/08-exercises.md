# 第 8 章　练习与考核

!!! abstract "怎么用本章"
    先做**综合项目**，再做**测验**。每项都有验收标准，对照检查即可，不需要老师批改。

## 8.1　综合项目：做一个你自己的只读 MCP

**任务：** 选一个你真实工作里的小数据源（CSV 转成 SQLite 也可以），做成一个 MCP 服务，让 AI 能用大白话查询它。

### 必须完成

| 编号 | 要求 | 验收方式 |
|---|---|---|
| A1 | 至少 4 个工具，其中至少 1 个是“按意图设计”的高层工具 | 看代码 |
| A2 | 每个工具都有符合“四要素”的描述 | 对照 4.2 |
| A3 | 只读，且至少有两层防线 | 看代码 |
| A4 | 返回有行数上限，并标明是否截断 | 调用大表查询验证 |
| A5 | 参数做了校验，没有字符串拼接 SQL | 看代码 |
| A6 | 依赖写在文件头，SDK 版本固定上限 | 看文件头 |
| A7 | 写了测试脚本，**包含至少 4 条“必须被拒绝”的用例** | 运行脚本，全部通过 |
| A8 | 接入 Claude Code，AI 能正确回答 3 个不同的问题 | 实际提问 |

### 加分项

- [ ] 提供一个 Resource（表结构）
- [ ] 提供一个 Prompt 模板（固定分析步骤）
- [ ] 注册表机制，支持多个数据源
- [ ] 一个“数据新鲜度”检查工具
- [ ] 把成果整理成一页使用说明

|---|---|

| 加分项，每项 | 4 分（共 20） |

## 8.2　测验

先自己作答，再展开看答案。

**1.** 用一句话说明 MCP 是什么。

??? success "答案"
    AI 应用与外部工具、数据之间的开放标准接口。

**2.** MCP 的三个角色分别是什么？“该用哪个工具”由谁决定？

??? success "答案"
    Host、Client、Server。由 **AI 模型**决定，不是 MCP。

**3.** Tool、Resource、Prompt 的区别？

??? success "答案"
    Tool：模型主动调用的动作；Resource：可阅读的资料；Prompt：用户选用的提问模板。

**4.** 为什么说工具的描述“就是模型的全部线索”？

??? success "答案"
    模型看不到代码，只能根据工具名、描述、参数来判断何时用、怎么用。

**5.** 客户端报 `Connection closed`，第一步应该做什么？

??? success "答案"
    脱离 AI，在终端里手动运行服务的启动命令，看真实报错。

**6.** “只读”为什么不能只靠在描述里写“请勿修改”？

??? success "答案"
    AI 可能忽略或被诱导。必须在程序里做死：只读打开 + 授权白名单 + 资源限制。

**7.** 黑名单和白名单，哪个更适合做权限控制？为什么？

??? success "答案"
    白名单（默认拒绝）。黑名单总会遗漏新的危险操作。

**8.** 什么是提示词注入？最有效的防御思路是什么？

??? success "答案"
    工具返回的内容里夹带指令，被 AI 当成命令执行。最有效的是**读写权限拆分**，并让敏感操作经过人工确认。

**9.** 密钥不小心推到了公开仓库，只把文件删掉够吗？

??? success "答案"
    不够，Git 历史里仍在。必须立即去服务商后台**作废该密钥并更换**。

**10.** 为什么装好 MCP 后要新开会话？

??? success "答案"
    MCP 在会话启动时才连接，已经开着的会话不会出现新工具。

**11.** 一个服务提供 40 个工具，有什么问题？

??? success "答案"
    占用大量上下文，AI 更容易选错工具，成本更高。应控制在 5~10 个，或拆分服务。

**12.** 一个会扣费的“生成视频”工具，应当怎样设计权限？

??? success "答案"
    加人工审批闸门：先申请（写明次数和预计花费）→ 人批准 → 才执行 → 事后核对并记账；批量、删除类操作直接禁用。

**13.** 为什么安全相关的修复之后，必须重新跑一遍“必须被拒绝”的测试？

??? success "答案"
    修复可能放松了某道防线（如为了放行合法操作而误开口子），只有回归测试才能证明防线依然有效。

**14.** 工具设计中“按意图”比“按技术”好在哪里？举例。

??? success "答案"
    参数固定、口径统一、不易出错。例如 `monthly_sales(month)` 比让 AI 自己拼 SQL 稳定。

**15.** 工具超时重试可能带来什么风险？怎么避免？

??? success "答案"
    非幂等的写操作会被重复执行（如重复扣款）。应让写操作幂等，或加唯一请求号去重。

### 成绩

答对 **13 题以上**：掌握扎实　**10～12 题**：基本掌握，回看第 4、5 章　**10 题以下**：建议重读第 1、5 章。

## 8.3　速查表

### 命令

```bash
claude mcp add 名字 -s user -- 命令 参数      # 装本地服务
claude mcp add --transport http 名字 地址      # 装远程服务
claude mcp list / get 名字 / remove 名字       # 管理
npx @modelcontextprotocol/inspector 启动命令   # 可视化调试
```

### 代码骨架

```python
# /// script
# dependencies = ["mcp>=1.2,<2"]
# ///
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("名字")

@mcp.tool()
def 工具名(参数: 类型) -> 返回类型:
    """做什么。何时用。参数格式（例）。限制。"""
    ...

if __name__ == "__main__":
    mcp.run()
```

### 一页纸原则

1. **按意图设计**，不按技术设计
2. **描述写四要素**：做什么 / 何时用 / 参数格式 / 限制
3. **参数窄、校验严、不拼接**
4. **返回有上限、标截断**
5. **错误信息可操作**
6. **5~10 个工具**
7. **读写分离**，写操作加人工审批
8. **只读靠程序做死**：多层 + 白名单
9. **先脱离 AI 测试**，含“必须拒绝”用例
10. **密钥不进仓库**，泄露即作废
